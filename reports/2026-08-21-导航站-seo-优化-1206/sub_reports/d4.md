# d4. 实施路线、风险与测量体系

## 本维度要回答的问题

1. 哪些工作必须先做，哪些可并行？
2. 每个阶段应交付什么并如何验收？
3. 应该跟踪哪些领先与滞后指标？
4. 如何控制批量内容、索引膨胀和错误数据风险？

## 搜索覆盖情况

本维度以 d1—d3 的问题、竞品差距和页面机会为输入，按依赖关系将工作拆成品牌/测量、技术索引、数据模型、内容试点、页面扩展和复盘六条工作流；再用 Google Search Console、sitemap、结构化数据与 spam policies 官方文档核对验收方式。当前代码表面已映射到 `site.ts`、`metadata.ts`、`robots.ts`、`sitemap.ts`、`pagination.tsx`、Sanity schema 和核心页面模板。所有 P0/P1 问题已有责任表面、顺序和验收条件，故停止本维度研究。

## 依赖顺序

```text
正式品牌与测量接入
  -> 抓取/索引/分页修复
    -> Sanity 字段与编辑政策
      -> 工具页与分类页试点
        -> alternatives/场景页小规模发布
          -> GSC 复盘后决定是否扩展
```

品牌和索引控制必须先完成，否则新增内容会继承错误站名并扩大低价值 URL 集合。Schema 字段和核验流程必须早于程序化页面，否则 alternatives 和派生品类会放大数据错误。技术修复与内容盘点可以并行，但批量发布必须等待验收门通过。

## 0—30 天：建立可索引的正式站点基础

### 目标

让站点从 Mkdirs demo 转为正式 AI 工具导航品牌，建立测量基线，修复会阻碍抓取、规范化和索引质量的 P0 问题。

| 工作流 | 具体交付 | 责任表面 | 依赖 | 验收 |
|---|---|---|---|---|
| 品牌与首页 | 确定站名、主价值主张、目标市场；替换 Title/H1/description、作者、邮件、社交、OG 图、导航和页脚模板文案 | 产品/品牌 + `src/config/site.ts`、首页组件 | 站点所有者给出真实品牌信息 | 全站抽样无 Mkdirs/demo；首页元数据和可见正文一致 |
| 测量基线 | 接入 GSC Domain Property、提交 sitemap；接入 GA4 或同类分析；记录日期、索引数、查询、落地页、自然会话和转化 | 站点所有者/分析 | DNS/账号权限 | GSC 验证成功；可查看 Page Indexing、Performance、Sitemaps |
| sitemap 治理 | 移除 search/auth/protected/不可索引 URL；lastmod 改真实更新时间或省略；按内容类型拆分 sitemap 以便监测 | `src/app/sitemap.ts`、Sanity 查询 | 品牌 URL 确定 | sitemap 只含 200、canonical、indexable URL；连续抓取未更新页 lastmod 不变 |
| noindex 与参数策略 | search/auth/dashboard/settings/edit/submit 等输出 `noindex, follow`；排序筛选参数不进入 sitemap；定义分页 canonical | 页面 metadata、`src/lib/metadata.ts`、routes | URL 清单 | 目标页 HTML robots 正确；第 2 页自引用 canonical；参数矩阵文档化 |
| 可抓取分页 | 将点击式 span 改为真实 `<a href>`/Next Link，保留当前交互 | `src/components/shared/pagination.tsx` | canonical 规则 | 禁用 JS 仍可沿 Previous/Next 和页码访问；链接返回 200 |
| 元数据修复 | `og:url` 使用当前 canonical；Twitter site/creator 使用真实账号或省略；校验 metadataBase | `src/lib/metadata.ts` | 正式品牌 | 首页/工具/分类/分页抽样一致；分享调试器预览正常 |
| 内容盘点 | 导出 1,105 个工具的描述、features、useCases、分类、标签、链接和更新时间完整度；识别重复/失效/低质量页 | Sanity 查询/脚本 + 编辑 | 无 | 形成可排序清单，标记 publish/index/noindex/draft 四种状态 |
| 性能基线 | 对首页、工具页、分类页做移动端 PageSpeed/Lighthouse；记录 LCP/INP/CLS、TTFB、图片字节和缓存头 | 工程/分析 | 线上品牌版发布前后均可 | 报告留档；不在无数据时声称 CWV 已通过 |

### 30 天退出条件

- 正式品牌已发布，核心页面不再出现模板文案。
- 低价值 URL 不在 sitemap 且输出正确 noindex；分页为可抓取 href。
- GSC/分析工具建立初始基线，至少完成 10 个代表 URL 的 URL Inspection。
- 内容盘点能筛出首批 50—100 个高优先工具和 5—8 个可升级品类。

## 31—60 天：建设可验证的页面价值

### 目标

扩展数据模型和编辑流程，完成小规模工具页、品类页与结构化数据试点，不追求数量。

| 工作流 | 具体交付 | 责任表面 | 依赖 | 验收 |
|---|---|---|---|---|
| Item schema | 增加 pricing model/free plan、platform、input/output、bestFor、limitations/pros/cons、official source、verifiedAt、editor 等字段 | `src/sanity/schemas/.../item.ts`、类型生成、查询 | 内容盘点字段定义 | `pnpm typegen` 后类型与查询通过；字段有来源和校验 |
| Category/Collection schema | 增加 editorial intro、selection criteria、FAQ、reviewedAt、featured items 和索引状态 | category/collection schema 与页面查询 | 首批主题确定 | 每个索引页满足 d3 准入门槛 |
| 编辑政策 | 发布 About/Editorial Policy：收录、验证、更新、下架、赞助/联盟披露、AI 使用规则 | 产品/编辑 + CMS 页面 | 正式品牌 | 页面公开可访问；工具页显示核验日期和责任信息 |
| 工具页试点 | 深度更新 50—100 个工具，修正标题、正文、决策字段、相关工具和可见更新时间 | 编辑 + 工具页模板 | schema 与政策 | 字段完整率达标；无无法证实措辞；抽样官网链接有效 |
| 品类页试点 | 升级 5—8 个窄品类，加入具体 H1、选择标准、比较维度、精选、子场景和 FAQ | 编辑 + 分类模板 | 合格工具库存 | 每页至少 8—12 个合格工具且有独特正文；无复制导语 |
| 结构化数据 | 首页 Organization/WebSite；层级页 BreadcrumbList；符合数据条件的工具页试点 SoftwareApplication | 根布局/页面模板 | 可见字段已完成 | Schema Validator/Rich Results Test 无关键错误；JSON-LD 与可见内容一致 |
| 图片与缓存 | 评估恢复图片优化或自建图片变体；修复公开静态页不必要的 private/no-store | `next.config.mjs`、图片 URL、响应头 | 性能基线 | 关键模板图片字节和 LCP 改善；功能无回归 |

### 60 天退出条件

- 首批工具与品类页达到字段、原创内容和更新来源门槛。
- 页面结构化数据通过校验且没有虚构 rating/review。
- GSC 已开始返回索引与查询数据；若仍无信号，先诊断索引/站点质量，不进入批量扩展。
- 失效、重复或极薄工具页已转草稿/noindex，而不是继续占用 sitemap。

## 61—90 天：用小规模高意图页面验证增长模型

### 目标

在已有数据质量和 GSC 信号基础上，发布少量 alternatives 与场景集群，建立更新、分发和复盘机制。

| 工作流 | 具体交付 | 责任表面 | 依赖 | 验收 |
|---|---|---|---|---|
| Alternatives 试点 | 10—20 个知名工具 alternatives 页；每页 5+ 候选、对称比较、替换原因、按场景推荐和核验日期 | schema/查询/新模板 + 编辑 | 两侧工具字段齐全 | 页面非拼接简介；候选真实可替代；内链双向完整 |
| 场景指南 | 3—5 个角色/工作流页，如 educators、writing workflow、real estate image editing | Collection/指南模板 + 编辑 | 品类与工具试点 | 按任务组织，有选择理由、限制和相关工具，不冒充实测 |
| 内链集群 | 首页—品类—场景—工具—alternatives 双向连接；HTML 链接与 Breadcrumb 一致 | 页面模板/内容关联 | 新页面发布 | 爬虫渲染可见 href；无孤儿索引页 |
| 更新机制 | 每周失效链接与价格抽查；每月更新重点页；保留变更记录；过期字段触发复核 | 编辑运营 + 自动检查 | verifiedAt 字段 | 核心页核验 SLA 达标；失效工具及时下架或标注 |
| 分发与权威 | 发布数据透明的月度精选/新工具简报；向被收录工具提供可引用页面；建立 Newsletter | 编辑/增长 | 正式品牌和高质量页 | 获得真实订阅、提及或自然链接；不交换操纵性链接 |
| 90 天复盘 | 按页面类型比较提交、索引、曝光、点击、CTR、查询、转化和维护成本 | 产品/分析 | 至少数周 GSC 数据 | 决定扩大、修改或停止每种页面模板 |

### 90 天退出条件

- 至少一个页面类型出现持续的非品牌 impressions 或 clicks；若无点击，也需能解释索引和曝光阶段的阻塞。
- alternatives/场景试点的索引率、字段错误率和维护成本处于可控范围。
- 只有通过质量门和 GSC 信号的模板才进入下一轮扩展；不以“发布页数”作为单一成功标准。

## KPI 与验收机制

### Day 0 必须记录的基线

- sitemap URL：当前 1,372；工具页 1,105；分页 URL 220；search/auth 3。
- 可观察公开搜索：暂未检出 `site:dir.vastnext.com` 结果，记为弱信号而非索引数。
- GSC：验证后记录 Submitted/Indexed/Excluded、Crawled currently not indexed、Discovered currently not indexed、Google-selected canonical。
- Performance：过去 28 天 impressions、clicks、CTR、average position，按 query/page/country/device 分组。
- 分析：organic sessions、工具官网点击、Newsletter signup、submit/付费转化。
- 性能：三种模板移动端 LCP、INP、CLS、TTFB 与图片总字节。

### 领先指标（每周）

| 指标 | 90 天目标/规则 |
|---|---|
| 模板残留 | 核心页面 0 处 Mkdirs/demo |
| sitemap 纯度 | 100% URL 为 200、canonical、indexable；search/auth/protected 为 0 |
| 可抓取分页 | 抽样 100% 含有效 href；无 JS 也可导航 |
| 核心工具字段完整率 | 首批 50—100 页达到 90%+ 必填字段 |
| 内容核验新鲜度 | 重点页 90% 在约定 SLA 内；建议 90 天内核验 |
| 失效链接率 | 首批核心页 <2%，并有处理 SLA |
| 结构化数据有效率 | 抽样页面无关键错误；字段与可见内容一致 |
| 发布质量门通过率 | 100% 新索引页通过库存、独特内容、来源和内链检查 |

### 滞后指标（每 28 天）

由于 Day 0 没有 GSC 数据，不设虚构的绝对流量目标，先用相对和阶段性指标：

- **发现**：有效 sitemap URL 的 discovered/crawled 比例持续上升。
- **索引**：合格试点 URL 的 indexed/submitted 比例；60—90 天目标可先设 ≥70%，若低于则暂停扩页并诊断。
- **曝光**：非品牌 impressions、获得 impressions 的页面数、获得 impressions 的查询数按 28 天环比增长。
- **点击**：organic clicks、CTR；按工具/品类/alternatives/场景拆分，不用站点总量掩盖模板问题。
- **排名分布**：进入 Top 100/50/20/10 的非品牌查询数；无可靠排名工具时用 GSC average position 分桶。
- **业务行为**：工具官网 outbound CTR、Newsletter signup rate、提交/付费转化；SEO 流量必须连接业务目标。
- **权威信号**：自然 referring domains、品牌查询、直接访问和 Newsletter 增长；不购买垃圾链接。

## 风险与控制

| 风险 | 触发场景 | 控制措施 | 停止条件 |
|---|---|---|---|
| 批量薄页/Scaled content | 自动为所有工具生成 alternatives/vs/筛选页 | 页面准入门、人工抽样、默认 draft/noindex、分波发布 | 错误率上升、索引率下降或无曝光时停止扩展 |
| 错误价格与功能 | AI/抓取数据无来源或过期 | officialSource、verifiedAt、编辑者、每周抽查、过期提示 | 无法核验的字段不展示，不使用“verified” |
| 索引膨胀 | 标签、筛选、排序、分页组合无限产生 | 白名单 sitemap、参数规范、弱 taxonomy noindex | 有效索引页占比下降时收缩 |
| 关键词蚕食 | 分类、集合、标签和指南承接相同词 | 每个词簇指定唯一主页面，重复页合并/重定向/canonical | GSC 多 URL 争同查询且表现分散时合并 |
| 伪 E-E-A-T/伪实测 | 使用 “tested”“best”“rating” 但没有过程 | 公开方法，只描述真实完成的审核；禁止虚构评分 | 无证据则改为 compare/directory 定位 |
| Schema 滥用 | 标记不可见价格、评分或评论 | JSON-LD 从同一可见字段生成，发布前自动校验 | 任何手动处罚/富结果警告立即下线问题标记 |
| 品牌依赖不确定 | 正式站名、作者、邮件、社交未确定 | Day 0 由站点所有者确认品牌资产 | 未确认前不发布全站 metadata 改造 |
| 测量延迟 | 新域名短期无 GSC 数据 | 保留技术/内容领先指标，28 天窗口评估 | 90 天仍无发现时优先诊断而非继续产页 |

## 对终稿的贡献

- 提供按依赖排列的 0—30/31—60/61—90 天计划、阶段退出条件和代码责任表面。
- 给出 Day 0 基线、周度领先指标、28 天滞后指标，以及在无历史数据时不虚构流量目标的测量方法。
- 将程序化 SEO 风险转为可执行的准入门、停止条件和更新 SLA。
- 明确正式品牌信息与 GSC 权限是实施阶段必须由站点所有者补齐的输入，但不阻塞本研究计划交付。

## 不确定性与空白

- 路线图按一个小型跨职能团队估算，未获得实际工程/编辑人力，因此未承诺工时和日历精度。
- GSC/GA 基线为空，所有索引率、曝光和转化目标需在接入后用首个 28 天数据校准。
- Sanity schema 变更会触发 `pnpm typegen`，具体查询和迁移范围需在实施计划中逐文件确认。
- 正式品牌名、作者实体、社交账号、编辑负责人和商业披露尚未由用户提供。

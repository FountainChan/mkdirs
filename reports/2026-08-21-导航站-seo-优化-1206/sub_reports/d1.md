# d1. 当前站点技术与页面 SEO 审计

## 本维度要回答的问题

1. 搜索引擎能否稳定发现并正确规范化有价值页面？
2. 哪些模板或参数 URL 可能制造重复、低价值或误索引？
3. 页面标题、描述、正文层级、内链和结构化数据是否支撑搜索意图？
4. 当前最严重的技术与内容阻塞项是什么？

## 搜索覆盖情况

研究执行了三层核验：先对线上首页、工具页、分类页、robots.txt、sitemap.xml 和公开搜索可见度做广度检查；再审计 Next.js 元数据、站点地图、分页、站点配置和图片配置代码；最后用 Google Search Central 与 Next.js 14 官方文档核对 canonical、noindex、sitemap、分页链接和批量内容要求。线上抽样覆盖首页、`/item/midjourney`、`/category/image-generation`，站点地图全量统计覆盖 1,372 个 URL。代码与线上输出相互印证，连续两轮没有出现会改变优先级的新事实，故停止本维度搜索。

## 关键发现

### 1. 搜索引擎可以访问页面，但站点向搜索引擎表达的是“模板演示站”而不是 AI 工具导航品牌

- 首页、工具页和分类页均返回完整 HTML，robots.txt 允许抓取，sitemap 可访问，因此不存在明显的全站抓取封锁。
- 但首页 Title、H1、description、页脚、作者和社交信息均突出 Mkdirs 模板；正式域名与模板品牌、通用站名 `Directory` 混杂。
- 这会让搜索引擎难以形成稳定的站点实体、主题和品牌信号，也是当前优先级最高的阻塞项。即使技术收录正常，页面仍主要匹配“directory website template”而不是“AI tools directory”。

### 2. sitemap 把“可访问 URL”混同为“希望进入搜索结果的高价值 URL”

- 线上 sitemap 共 1,372 个 URL，其中 `/search` 1 个、认证页 2 个、分页 URL 220 个，占约 16.0%。
- `/auth/login`、`/auth/register` 和裸 `/search` 不承载有竞争力的自然搜索落地价值；目前既在 sitemap，又没有页面级 noindex 证据。
- 静态入口、法律页和认证页统一使用 sitemap 生成时刻作为 `lastmod`；30 个首页分页也统一使用运行时当前时间。代码中的 `new Date()` 证明该信号不是内容真实更新时间。
- 分类与标签分别形成 84 和 143 个 sitemap URL。若条目集合和介绍高度相似，会形成近重复聚合页；弱标签不应仅因存在于 CMS 就自动进入索引集合。

### 3. 深层列表发现依赖 sitemap，分页内链本身不可稳定抓取

- 分类页服务器 HTML 中 Previous、页码和 Next 均为 `span`，没有 `href`。
- 组件通过 `onClick` 调用 `router.push`。Google 官方明确指出爬虫通常发现 `<a href>`，不会可靠触发依赖用户操作的 JavaScript。
- 因此 sitemap 虽列出了分页 URL，但站内链接图没有向搜索引擎提供稳定的顺序发现路径，也缺少描述性锚文本上下文。若 sitemap 或渲染出现问题，深层工具发现会显著受损。

### 4. canonical 基础存在，但分页 canonical 与社交元数据需要纠正

- 抽样首页、工具页、分类页均有 canonical，是现有实现的正面基础。
- 详情页和分类页的 `og:url` 却固定为首页，造成社交分享实体与 canonical 不一致；Twitter `site` 使用 URL，`creator` 使用 `Mkdirs`，也不是规范的站点账号表达。
- 分页 URL 是否自引用 canonical 必须逐页验证。当前页面级生成逻辑若忽略 `page` 参数，可能把第 2 页及以后 canonical 到第一页，与 Google 对分页独立 URL 的建议冲突。

### 5. 页面模板具备正文基础，但搜索意图与差异化仍明显不足

- Midjourney 工具页已有简介、Key Features、Use Cases、分类、标签和相关推荐，优于只有一句简介的薄页。
- 但其品牌后缀仍为 `Directory`，发布日期显示为 2026/08/18，而没有“资料核验/最后更新”语义、编辑者、数据来源、定价状态、平台、输入输出、优缺点、替代品比较等信任与决策信息。
- Image Generation 分类页 Title 和 description 能指向主题，但 H1 只是 `Category`；正文几乎是分类导航和工具列表，缺少独特导语、选择标准、子主题、编辑精选、FAQ 或比较框架。
- 首页虽然展示大量工具，但核心标题与正文完全错位，无法承接 “AI tools directory”“best AI tools”“latest AI tools”等主要意图。

### 6. 完全缺失结构化数据，且可视面包屑没有机器可读对应物

- 代码与三页线上 HTML均未发现 `application/ld+json`。
- 可优先为全站增加 `Organization`/`WebSite`，为层级页增加 `BreadcrumbList`；工具页只有在可见内容与字段真实完整时再考虑 `SoftwareApplication`。评分和评论不得伪造。
- 结构化数据不是排名捷径，但能帮助机器理解站点实体、层级和软件条目属性；Google 官方要求标记内容必须与用户可见内容一致。

### 7. 性能存在配置级风险，但不能在无现场数据时断言 Core Web Vitals 不合格

- `next.config.mjs` 将 Next Image 的 `unoptimized` 设为 `true`，目录卡片和截图规模扩大后会增加图片字节、LCP 与带宽风险。
- 此前观察到的全局私有 no-cache/no-store 响应策略需要针对静态公开页复核；若属实，会削弱 CDN 缓存和响应速度。
- 本次没有 CrUX、PageSpeed、GSC CWV 或浏览器性能跑分，因此只能将其列为需要测量的工程风险，不能给出“不达标”结论。

### 对四个关键问题的回答

1. **能否稳定发现并规范化页面？** 基础可访问且有 sitemap/canonical，但不能称为稳定：分页 href 缺失、低价值 URL 混入 sitemap、分页 canonical 未完成验证。
2. **哪些 URL 有重复或误索引风险？** `/search`、认证页、排序/筛选参数、弱标签、分类/标签高度重叠页，以及没有独立语义的深分页页。
3. **页面元素是否支撑意图？** 工具页部分支撑品牌工具词；首页和分类页明显不足；结构化数据缺失，品牌元数据错误。
4. **最严重阻塞项是什么？** 不是 URL 数量不足，而是正式品牌定位尚未上线，其次是索引集合治理与可抓取分页。

## 不确定性与空白

- 无 GSC，无法确认 Google 实际发现、抓取、索引和 canonical 选择情况；公开 `site:` 检索只能作为弱信号。
- 无 GA，无法确认自然流量、落地页和转化基线。
- 无 CrUX/PageSpeed 实测，性能结论仅为配置风险。
- 未逐一审计 1,105 个工具页的内容重复率、事实准确性和字数分布。
- 未完成分页第 2 页 canonical、越界页 HTTP 状态、筛选/排序参数矩阵的逐项线上测试，应在实施前补充自动化抽样。
